# Isolated Vulkan benchmark queue

These scripts preserve the local synthetic evaluation workflow; they are not a production deployment. They assume an existing `rupert-test` Incus container, a prepared synthetic test database at `/tmp/rupert-120-benchmark.sqlite3`, a fixture checkout at `/tmp/rupert-benchmark-audit/web`, the specified Ruby and gem paths, and already captured encrypted cohorts. They do not create the fixture, download models, or run the cloud baseline. The fixture checkout must include the 120-second answer deadline and the comparison task. Do not point the workflow at a production database or use real customer data.

Set `RUPERT_BENCHMARK_MODEL_ROOT` to the model and Vulkan-build directory, `RUPERT_BENCHMARK_OUTPUT` to an existing private **local** evidence directory, `RUPERT_BENCHMARK_FIXTURE_DIR` to the cohort/report directory inside the fixture container, and `RUPERT_BENCHMARK_GRADER_KEY` to the isolated grader credential. Do not commit the credential, model files, cohorts, fixture data, or generated reports. The runner sends the credential through standard input, not a command-line argument. Check local memory, available GPU, container access and the configured network route before starting. It starts a local server on loopback port 18081 and expects that port to be free.

`run-gpu.sh` serializes models and question sets, saves reports locally, and calls `compare-ready.sh` to create paired comparisons when the baseline and candidate have both finished. The comparison task validates the cohort; matching means alone do not establish comparability. The fixed evaluation date and model settings reproduce this experiment and should be changed only for a separately labeled cohort. The scripts do not schedule themselves or copy performance evidence to a NAS.
