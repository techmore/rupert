Deployment

Rupert deploys to a DigitalOcean droplet via Docker, straight from a push to main.

How deploys work

The deploy.yml workflow runs on every push to main: it builds the Docker image, pushes it to GitHub Container Registry, then SSHes into the droplet to docker compose up -d. The PostgreSQL database lives in a Docker volume and survives deploys.

First-time droplet setup

  1. Create a droplet with Docker (e.g. Ubuntu + the Docker image).
  2. Add GitHub secrets to the repo:
    • GHCR_TOKEN — PAT with packages:write
    • DROPLET_HOST, DROPLET_USER, DROPLET_SSH_KEY
  3. On the droplet, create /opt/rupert/.env (copy from .env.example):
    • SHOPIFY_API_KEY / SHOPIFY_API_SECRET / HOST (public HTTPS URL)
    • SQUARE_ACCESS_TOKEN (+ optional SQUARE_LOCATION_ID)
    • SECRET_KEY_BASE (bin/rails secret)
    • RAILS_ENCRYPTION_PRIMARY_KEY / DETERMINISTIC_KEY / KEY_DERIVATION_SALT (bin/rails db:encryption:init) — keep these stable; encrypted settings are unreadable if they change
  4. Push to main — the workflow deploys automatically.

Backups

Use the Settings page's Database backup (download a snapshot) or a volume snapshot. Google Drive backups can also be enabled for automatic snapshots every 6 hours.

Continuous integration

CI runs in the official ruby:4.0 container against a PostgreSQL service: RuboCop, migrations, Tailwind build, asset precompile, and the full test suite. Every push to main or a pull request triggers it.
