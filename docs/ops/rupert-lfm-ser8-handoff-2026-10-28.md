## What changed and why

The work focused on server-side tool selection, evidence handling and response construction around LFM3, with the same runtime available to other models. It did not train model weights. Important changes include:

- Preserve explicit reporting dates, comparisons and currency separation when a model chooses conflicting lookup arguments; route certain bounded questions to authorized metric evidence.
- Distinguish recorded sales, cash flow, payroll affordability, processor deposits, refund transactions and refunded-order status. Missing records are not treated as proof of zero or complete source coverage.
- Fetch and render specific upload, bank-line, receipt, compliance and retention evidence separately; prevent unrelated counts from being presented as the answer. Deny action proposals on instruction-only requests.
- Reserve evidence for adjustable daily charts, validate chart rows against dates, sources, currencies and values, and support a bounded month-over-month chart with missing values blank. Respect source, product and other filters.
- Preserve valid ISO dates in redacted output and bound oversized responses with an explicit omission notice. Isolate payment-reconciliation test locks to prevent parallel test workers interfering with each other.
- Add `depth`, `breadth` and `visualization` benchmark modes, frozen cohorts, checkpointed batches and offline review. See [benchmark modes](team-chat-benchmark-modes.md) for the intended behavior.

These changes were exercised by focused unit/integration tests, lint and targeted live replays on synthetic data. Replays of a known failure show the requested fix can work on that case; they do not establish general improvement. Relevant broader test runs included 175 tests / 1,041 assertions for agent, compliance and financial handling; the latest documentation-triggered GitHub CI run was pending at this checkpoint. A full GitHub run had previously passed after the payment-lock isolation fix.
