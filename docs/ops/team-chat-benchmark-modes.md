# Team chat benchmark modes

`BATTERY=depth` combines the current general, finance, cross and visualization sets, including workspace edits, into one run. These questions have authored expectations and tool checks, but each reference still needs review for whether it actually supports the question. Cross-set duplicate IDs are rejected. Edited constituent sets produce a distinct depth run name.

`BATTERY=breadth` includes every question in the question bank, including answerable, partial and unanswerable labels. The bank currently has 2,500 entries. Its labels and tool-routing expectations are not verified factual answers; questions without suitable authored reference arguments or expectations remain ungraded. Breadth and depth are recorded under separate set names. `BATTERY=bank` remains the earlier deterministic per-area sample and is not the full bank.

Both modes default to `GRADER=offline`: answers are stored in the test room for independent review, and no automated grade is assigned. This controls the **grader**, not the answering model: select a local agent and an isolated synthetic or local private database if data must remain local. Do not enable a hosted model, verifier or hosted grader for private records. Legacy individual sets retain their existing grader default; `GRADER=offline` can be used for those too. `GRADER=hosted` explicitly requests the configured hosted grader and may transmit question, answer and references.

`BATTERY=visualization` runs the side-panel questions alone and also defaults to independent offline review. Each result records whether a structured table or chart was produced, its row count, whether it supports the panel controls, and how many figures were not found by the existing numeric check. A zero unmatched count does **not** verify that figures belong to the correct row, source, currency or period. Review those relationships against the captured reference; a missing view is not a successful chart. Controls adjust chart type, selected series and the displayed row range of the returned snapshot; fetching a different source or a wider date range requires a new view. HTML views do not offer these structured controls.

The existing `team_chat:battery_cohort` task captures an encrypted reference cohort for any of these sets. Use the same requester, question version, fixture and cohort for a comparison. Cohorts check that reference evidence and the calendar date have not changed; a long breadth run may cross that boundary, and ungradable or changed references must not be silently scored. Full breadth takes far longer than depth on one local GPU. Retain failures and ungraded answers in the analysis, and compare repeat runs and held-out phrasings rather than tuning to one question.

For example, on a deliberately isolated fixture, an operator can capture a `BATTERY=depth` or `BATTERY=breadth` cohort and run `team_chat:battery` with that same `BATTERY`, `COHORT`, local `AGENT` and `GRADER=offline`. Results appear in the run's private test room. The Test questions page also offers both combined modes with a local bot and independent review; it continues to edit individual sets. A live workspace run uses that workspace's data and permissions, whereas an isolated fixture run uses its own data.

In the 2026-10-28 corrected synthetic breadth capture, 1,537 entries had neither a reference nor an authored expectation and 19 navigation lookups failed. Of the remaining 944 entries, 611 had an expectation but no reference and 333 had a nonempty reference. Those 333 include navigation references and still need individual scope checks; they are not a measured count of fully gradeable factual questions. These figures are fixture- and requester-specific and can change as the bank improves.
