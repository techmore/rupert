# Wells Fargo connection and transaction sync

Open **Finance → Bank statements → Connect or manage Wells Fargo**. The feed is optional and tenant scoped. It reads posted USD transactions from Wells Fargo checking and savings accounts through Plaid; it does not move money, fetch real-time balances, or record expenses automatically.

## Setup and bank consent

1. A user with both `finance.write` and `settings.write` saves the workspace's Plaid Client ID, environment-specific secret and environment. Values are encrypted and never rendered back into the form. Blank fields preserve saved credentials only in the same environment. Changing environments clears saved credentials. Connected credentials cannot be replaced until Disconnect completes.
2. In the Plaid dashboard, register the exact public URL `https://YOUR_RUPERT_HOST/bank_connection` as an allowed redirect URI. Production requires HTTPS. Configure the app to be opened directly in its own browser tab for the bank OAuth flow.
3. Obtain Plaid Transactions production access and institution OAuth approval for Wells Fargo. Client credentials do not establish bank consent. Check institution availability in your own Plaid dashboard; the code does not assume an institution ID or promise access to every Wells Fargo account type.
4. A finance writer presses **Connect Wells Fargo**, chooses Wells Fargo in Plaid Link, and authorizes the bank accounts. Rupert never requests or stores the Wells Fargo password. The server exchanges the one-use public token, checks `/item/get` and `/institutions/get_by_id`, and rejects/revokes an Item belonging to another bank. This version supports one Plaid Item per workspace and all supported accounts consented under that Item.
5. Connecting enables hourly reads and queues the first sync. **Sync now** queues another read. Plaid may initially return no transactions; subsequent hourly reads retrieve data when it becomes available. **Reconnect** uses Link update mode, preserving the Item and cursor. It does not exchange a replacement public token.
6. **Disconnect** pauses local sync first and calls `/item/remove` before clearing encrypted access. If revocation fails, sync stays paused and the token is retained for retry. Already imported lines and encrypted source evidence remain available. Revocation can also be checked in the bank's connected-app controls.

OAuth returns to the same finance page. The original Link token is held in the signed/encrypted Rails session, bound to the user, workspace, environment and Item, with a 30-minute limit. On return, the client reinitializes Link with that token and `receivedRedirectUri`. JSON endpoints require authenticated finance write permission and Rails CSRF protection. Credentials, public/access/Link tokens and OAuth state are filtered from request logs; responses are no-store and send no referrer.

## Import semantics and review

- Initial consent requests up to 90 days of history. Sync uses `/transactions/sync` with a persisted encrypted cursor, fetching at most 100 pages of 500 updates per run. A pagination mutation restarts the entire fetch from the original cursor, up to three attempts. Other errors retain the original cursor for the next run.
- The PostgreSQL connection row lock serializes sync, consent changes and revocation; SQLite uses its transaction writer lock and can refuse a concurrent write for a later retry. Every page is fetched before applying updates. Evidence, feed entries, review lines and the final cursor commit in one database transaction. Failed imports cannot advance the cursor or leave partial review lines. Solid Queue also limits concurrent jobs per workspace.
- Provider transaction IDs are hashed with Item identity for unique feed entries. Amounts use integer cents: Plaid's positive withdrawals become negative cash movements. Non-USD or unsupported account data fail the batch with an explicit code. Pending and zero-value transactions are retained as encrypted source evidence but never become reviewable expense lines. Pending-to-posted replacements therefore create only the posted review line.
- Source details are retained as encrypted JSON evidence under `bank_statement`, labelled with the environment. No full bank account numbers or balances are stored. Account labels use subtype and a short hash of the provider account ID, never a supplied full account number.
- Changes to undecided transactions update the review line while retaining both source revisions. Removals keep the line, mark it removed and ignore it before review. A reinstated transaction removed by the feed before review returns to pending. Human decisions are preserved.
- Changes or removals after a line was recorded flag the original line. **Wells Fargo → Bank changes to recorded lines** compares the latest source details with the original entry; **Books Check** also flags them. Expenses and vendor payments are never rewritten automatically. Make any required accounting correction through the existing expense/payment workflow. Flags remain as an audit warning; this version does not implement an automatic correction or acknowledgment workflow.
- Locked accounting periods block importing or changing the affected lines. The job displays `REVIEW_REQUIRED` and retains its cursor. Review the locked period using the established accounting controls before retrying; no lock is bypassed.
- CSV deduplication and feed ID deduplication are separate. Avoid overlapping CSV imports with the feed. Disconnecting and linking a new Item may provide new transaction IDs for overlapping history; use **Reconnect** for consent renewal and check any overlap before recording. Do not treat feed credits as new sales: the existing decision screen permits deposits to be ignored only.
- Hourly polling retrieves Plaid's latest available data. It does not call the separately billable `/transactions/refresh` endpoint or promise hourly bank freshness. This version uses polling rather than a public webhook endpoint.

## Deployment and verification

Run normal release checks, back up the database and encryption keys, run `bin/rails db:migrate`, build assets, and restart the web and Solid Queue processes so the new hourly `bank_feed` schedule loads. No new gem or environment variable is required. Setup is stored per tenant in encrypted `bank_connections` rows.

Use a separate test workspace for Sandbox, which produces clearly labelled test lines. Verify Link opening, OAuth return, successful first sync, later transactions, update-mode reconnect, and revocation using your own Plaid sandbox configuration before enabling Production. Sandbox code paths and HTTP contracts are covered by mocked tests; real bank consent and production entitlement require a live acceptance check with authorized credentials. Never put bank data, API secrets, browser sessions or test exports in Git.

Official contracts: [Plaid OAuth](https://plaid.com/docs/link/oauth/), [Link API](https://plaid.com/docs/api/link/), [Transactions Sync](https://plaid.com/docs/api/products/transactions/#transactionssync), [Items API](https://plaid.com/docs/api/items/), [Institutions API](https://plaid.com/docs/api/institutions/).
