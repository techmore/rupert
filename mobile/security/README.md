# Expo-compatible security backports

Expo 58.0.17 / React Native 0.88.0 stay on the SDK-supported dependency matrix. Never run `npm audit fix --force`: its proposed SDK downgrades are incompatible with this app. Signing, account connection, cloud builds and store submission remain deferred.

| Underlying advisory | Remediation |
| --- | --- |
| [UUID buffer bounds, GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq) | Expo's compatible dependency tree now uses `xcode` 4.0.0, which removes UUID in favor of Node's `crypto.randomUUID()`. The obsolete override is removed; tests verify dependency removal and unique 24-character project identifiers. See [upstream release notes](https://github.com/apache/cordova-node-xcode/blob/4.0.0/RELEASENOTES.md). |

These are local backports, not newly published upstream releases. Sources: [braces report](https://github.com/micromatch/braces/issues/70) and the [deepmerge advisory](https://github.com/advisories/GHSA-gcqx-w48m-w2h4).

`backports.json` records exact upstream versions, before/after SHA-256 hashes and minimal replacement text. `postinstall` validates all sources before writing; repeated application is idempotent. Unknown versions or modified sources fail closed. Do not skip install scripts. `verify:security` also fails if any reviewed patched file is missing or altered, so bypassing postinstall cannot pass `npm run check`.

`audit:security` verifies source hashes, fetches the current npm advisory graph, and permits only the exact advisory URLs above and packages whose findings resolve to those verified backports. New advisories, unexplained findings and audit network failures fail the check. The full raw registry report and the disposition are retained in `dist/dependency-security.json` and in CI's unsigned export artifact. As of this update, raw npm audit reports only the backported `braces` and `deepmerge` findings and their dependents. The verified patched-source gate reports zero unremediated advisories; it does not alter package versions or suppress npm's report.

Before signing, run `npm ci`, `npm run check`, Expo Doctor and both normal Hermes exports. Recheck upstream releases: once a compatible fixed version exists, replace its backport with the supported dependency update, remove its manifest entries and advisory allowance together, then rerun the exploit regressions, Expo compatibility, native prebuild and both platform exports. Never add a new allowance without a reviewed source fix and meaningful regression coverage.
