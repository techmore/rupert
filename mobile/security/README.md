The braces change is a local backport, not a newly published upstream release. Source: [braces report](https://github.com/micromatch/braces/issues/70).

`backports.json` records exact upstream versions, before/after SHA-256 hashes and minimal replacement text. `postinstall` validates all sources before writing; repeated application is idempotent. Unknown versions or modified sources fail closed. Do not skip install scripts. `verify:security` also fails if any reviewed patched file is missing or altered, so bypassing postinstall cannot pass `npm run check`.

`audit:security` verifies source hashes, fetches the current npm advisory graph, and permits only the exact advisory URLs above and packages whose findings resolve to those verified backports. New advisories, unexplained findings and audit network failures fail the check. The full raw registry report and the disposition are retained in `dist/dependency-security.json` and in CI's unsigned export artifact. Raw npm audit identifies upstream versions, so it can still report the backported `braces` finding and its dependents; when this was last updated (Expo 58.0.25) it reported no findings. The verified patched-source gate reports zero unremediated advisories; it does not alter package versions or suppress npm's report.

Before signing, run `npm ci`, `npm run check`, Expo Doctor and both normal Hermes exports. Recheck upstream releases: once a compatible fixed version exists, replace its backport with the supported dependency update, remove its manifest entries and advisory allowance together, then rerun the exploit regressions, Expo compatibility, native prebuild and both platform exports. Never add a new allowance without a reviewed source fix and meaningful regression coverage.
